# Сценарии за хардуерно изпитване

Това е план за експерименти, а не протокол за изпълнена симулация. Съответните сървърни правила са проверени автоматизирано; поведението на физическо устройство трябва да се наблюдава отделно.

## Предварителни условия

Работещ backend, активна прожекция, поне два валидни билета, отделни ключове за kiosk и validator, синхронизиран сървърен часовник и документирана схема. Използвай тестови потребители и измислени картови данни.

| ID   | Стимул                                               | Очакван резултат                           | Хардуерен резултат |
| ---- | ---------------------------------------------------- | ------------------------------------------ | ------------------ |
| H-01 | Валиден код и правилна прожекция                     | Един положителен отговор; green/вход       | Предстои           |
| H-02 | Повторно въвеждане на H-01                           | `already_used`; red/без вход               | Предстои           |
| H-03 | Валиден код за друга прожекция                       | `wrong_showtime`; кодът не се използва     | Предстои           |
| H-04 | Несъществуващ шестцифрен код                         | `invalid_code`; без вход                   | Предстои           |
| H-05 | Прекъсната мрежа / timeout                           | Без локално разрешение за вход             | Предстои           |
| H-06 | Отзован ключ                                         | 401; без вход                              | Предстои           |
| H-07 | Един код от два валидатора едновременно              | Точно един успех                           | Предстои           |
| H-08 | Код за приключила прожекция                          | `expired`; без вход                        | Предстои           |
| H-09 | Сайтът задържа място, kiosk го избира                | Конфликт 409; няма двойна продажба         | Предстои           |
| H-10 | Учебна транзакция без успешен резултат               | Без код; освободено място                  | Предстои           |
| H-11 | Изгубен checkout отговор и повторение със същия hold | Същата поръчка и код                       | Предстои           |
| H-12 | Непълни цифри, `*`, `#`                              | Няма невалидна заявка; правилно изчистване | Предстои           |

## Формат на протокола

За всеки сценарий запиши дата и час, Git SHA на софтуера/firmware, модел на платката, версия на симулатора, схема, мрежов режим, HTTP статус/`reason`, наблюдаван индикатор и заключение. Не включвай device ключове или лични данни. Използвай нов билет за всеки тест, който го консумира.

За оценка на времето за отговор са нужни реални измервания с описан брой повторения. Не са предоставени измислени времена или твърдения за производителност.
