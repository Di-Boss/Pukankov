# Билетен терминал · ESP32

Сензорен терминал за покупка на до **8 места наведнъж** от същата програма и база, които използва сайтът. Firmware: `kiosk-9`.

## Стартиране

1. В ESP32 Wokwi проект добави `sketch.ino`, `diagram.json` и библиотеките от `libraries.txt`.
2. Стартирай [публичния API](../../../software/docs/public-device-api.md) и изчакай Wi-Fi връзката към `Wokwi-GUEST`.
3. В Serial Monitor изпрати `URL https://YOUR-DOMAIN`, после `KEY YOUR_KIOSK_KEY`. Използвай ключ с роля `kiosk`; стойността не се показва обратно.
4. Избери филм → прожекция → едно до осем свободни места → плащане. Докосването на избрано място го премахва.
5. Прочети RFID карта. Успешният прочит подава `payment_success: true`; UID не се изпраща към API. След потвърждение прелисти отделните билети и шестцифрените им кодове.

[Оригинална Wokwi симулация](https://wokwi.com/projects/479132501119948801)

## Обмен с API

| Операция | Маршрут |
| --- | --- |
| Каталог | `GET /api/v1/devices/movies` |
| Програма | `GET /api/v1/devices/showtimes?movie_id=…` |
| Свободни места | `GET /api/v1/devices/showtimes/{id}/seats` |
| Задържане | `POST /api/v1/devices/bookings/holds` |
| Отказ | `DELETE /api/v1/devices/bookings/holds/{id}` |
| Приключване | `POST /api/v1/devices/payments/checkout` |

Цените и наличността идват от сървъра. Преди изпращане на плащането терминалът запазва задържането в NVS. При прекъсване повтаря същата операция, за да не създава дублирана покупка. Пълният отговор с билетите се запазва преди изчистване на чакащото плащане.

## Свързване

| Компонент | ESP32 GPIO |
| --- | --- |
| Общ SPI: SCK / MISO / MOSI | 18 / 19 / 23 |
| ILI9341: CS / DC / RST | 5 / 2 / 4 |
| FT6206: SDA / SCL | 21 / 22 |
| MFRC522: CS / RST | 15 / 13 |
| RGB общ анод: R / G / B | 25 / 26 / 27 |
| Buzzer | 12 |

MFRC522 и подсветката са на 3,3 V; захранването и общата маса са показани в `diagram.json`. Дисплеят и RFID споделят SPI с отделни chip-select линии. Кирилицата се изписва с U8g2, включително надписите на жълтите бутони.

## Диагностика

Команди: `STATUS`, `DIAG`, `RETRY`, `HELP`, `URL …`, `KEY …`, `PIN …`. Адресът и ключът се запазват локално. За зададения ngrok хост firmware проверява SHA-256 отпечатъка и срока на сертификата; при смяна на сертификата обнови отпечатъка според [инструкциите](../../../software/docs/stable-public-api.md). За други хостове се използват вградените CA сертификати.

Проектът съдържа и `platformio.ini` за компилация извън Wokwi. RFID е учебно потвърждение на плащане; няма банкова обработка.
