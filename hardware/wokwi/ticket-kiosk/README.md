# ESP32 автомат за билети

**Статус: подготвена спецификация; няма изпълнена Wokwi симулация.**

## Предназначение

Продажба на място със същите свободни места и цени като сайта. Терминалът не поддържа собствена независима база и не генерира кодове локално.

## Планирани компоненти

- ESP32 с WiFi връзка.
- Дисплей за прожекции, места, цена и резултат.
- Бутони или keypad за навигация и потвърждение.
- Симулационно действие за успешна/отказана транзакция.

GPIO назначенията и конкретният дисплей трябва да се фиксират заедно със схемата. След реализация тук се добавят `sketch.ino`, `diagram.json`, зависимости и инструкции за повторение. Не се включва частен device ключ.

## Състояния

`Свързване → Програма → Място → Задържане → Учебно плащане → Код / Отказ`

При 409 за място презареди наличността. При изтекъл hold започни нов. При неизвестен резултат от checkout повтори със същия hold ID; не създавай автоматично втора поръчка. При отказ освобождаването е сървърна операция.

## API последователност

1. `GET /api/v1/devices/showtimes`
2. `GET /api/v1/devices/showtimes/{id}/seats`
3. `POST /api/v1/devices/bookings/holds`
4. `POST /api/v1/devices/payments/checkout`
5. Покажи `tickets[].ticket_code` само при `success:true`.

Удостоверяване: `Authorization: Bearer ...` с роля `kiosk`. Виж [договора за устройства](../../../software/docs/devices.md).

## Критерии за приемане

Място, задържано от сайта, не може да се купи от автомата. Отказана транзакция не издава код. Повторен checkout не дублира билет. Издаденият код се приема еднократно от валидатора за правилната прожекция. Тези правила вече са проверени на API ниво; предстои проверка през firmware.
