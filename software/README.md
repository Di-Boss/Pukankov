# Пуканков — твоето място е в киното

Софтуерен компонент на дипломния проект. [Общ преглед и академичен обхват](../README.md) · [Хардуерна част](../hardware/README.md).

Работеща локална демонстрация на българска кино платформа: React + TypeScript + Vite, FastAPI + SQLAlchemy, PostgreSQL чрез Docker или SQLite за лесно стартиране.

**Демо среда, без реални плащания.** Кината, адресите, програмата, рейтингите и офертите са демонстрационни. Публичното търговско внедряване изисква допълнителната работа, описана по-долу.

## Бързо стартиране на Windows

Нужни са Node.js 22+ и Python 3.11+ (проверено с Node 24 и Python 3.13).

Отвори PowerShell в тази папка:

```powershell
.\start.ps1
```

За вече подготвеното копие отвори `START-SITE.cmd` с двоен клик и остави терминала отворен. Той стартира миграциите, допълва програмата и пуска сайта със съществуващата база. При първоначална инсталация използвай `start.ps1`.

Скриптът инсталира зависимостите, компилира сайта, мигрира и зарежда базата и стартира **http://127.0.0.1:8000**. Спира се с Ctrl+C. Не променя execution policy на системата. Ако PowerShell блокира скрипта, изпълни ръчно командите по-долу.

## Разработка: два терминала

Frontend, от корена на проекта:

```powershell
npm ci
npm run dev
```

Backend, във втори терминал:

```powershell
cd backend
python -m pip install -r requirements.txt
python -m alembic upgrade head
python -m app.seed
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Отвори **http://127.0.0.1:5173**. Vite препраща `/api` към FastAPI. OpenAPI: **http://127.0.0.1:8000/api/docs**. Backend не създава таблици автоматично при import — миграцията е задължителна.

За един сървър: изпълни `npm run build`, после стартирай backend както по-горе и отвори порт 8000. Той обслужва и `dist/`, включително директно отваряне на React маршрутите.

## База данни и настройки

Без конфигурация се използва `backend/pukankov.db`. Всички данни се запазват между рестартиранията. `python -m app.seed` създава 15 авторски измислени филма, 3 кина, 6 зали, 504 места, 2 промокода и бъдеща демо програма за следващите 7 дни. Повторното изпълнение добавя липсващите бъдещи слотове и не изтрива поръчките. Старият каталог се скрива от публичните списъци; историята на покупките се запазва. Миграция `0002` преобразува съществуващите билети в шестцифрени кодове, включително вече използваните.

Копирай `.env.example` като `backend/.env`, ако искаш различни настройки. За PostgreSQL задай например `DATABASE_URL=postgresql+psycopg2://USER:PASSWORD@localhost:5432/pukankov`, после изпълни миграцията и seed командата. Паролите в URL трябва да бъдат URL-encoded.

В Docker: копирай `.env.example` в `.env` в корена и попълни `POSTGRES_PASSWORD` с нова случайна шестнадесетична стойност, например генерирана с `python -c "import secrets; print(secrets.token_hex(24))"`.

```powershell
docker compose up --build
```

Приложението е на **http://127.0.0.1:8000**, PostgreSQL е във вътрешна мрежа с постоянен volume. Docker daemon не беше достъпен в средата на изработка; този път за стартиране е предоставен, но не е изпълнен тук.

## Профили и администратор

Няма публични или фиксирани администраторски пароли. Създай потребител от `/register`. Създай първия администратор интерактивно от `backend/`:

```powershell
python -m app.cli create-admin --email you@example.com --name "Твоето име"
```

Командата иска нова парола два пъти, не я показва и не променя съществуващ потребител. После влез от `/login` и отвори `/admin`. В Docker използвай `docker compose exec app python -m app.cli create-admin --email you@example.com`.

Роли: user, staff, admin. Само администратор променя ролите на други потребители; не може да отнеме собствените си права. Staff има достъп само до проверката на билети в контролния панел. Backend проверява правата на всяка защитена операция.

## Демо покупка

1. Регистрирай профил.
2. Отвори „Прожекции“ и избери слот.
3. Избери едно или повече места и продължи.
4. По желание въведи `KINO20` (20%, минимум 18 €) или `STUDENT15` (15%, минимум 9 €). Лимит: 2 използвания на потребител, 100 общо.
5. Натисни „Попълни примерна карта“ или въведи измислени данни. Отметни „Успешна транзакция“, приеми условията и натисни „Плати“. Без отметката транзакцията се отказва, няма билет и местата се освобождават.
6. Виж билетите с уникални шестцифрени кодове в „Моите билети“. „Печат / Запази като PDF“ отваря системния print dialog — избери Save as PDF.

**Има учебна картова форма, без реална банкова транзакция.** Номерът, името, валидността и CVV остават само в React паметта на страницата; не се изпращат до API и не се съхраняват. Сървърът получава само hold ID, промокод, съгласие и избрания резултат на симулацията. Не изпращаме имейл с билет в текущата версия. Той е наличен в профила. SMTP настройките поддържат защитено възстановяване на парола; без тях интерфейсът изрично казва, че услугата не е конфигурирана.

## Проверки

Последни проверки: **56 backend сценария, 15 браузърни сценария и production build (29.10.2026).** Подробности: [docs/verification.md](docs/verification.md).

```powershell
npm run build
cd backend
python -m pytest tests -q
```

E2E, от корена, след инсталиране на Python зависимостите:

```powershell
npx playwright install chromium
npm run test:e2e
```

В среда без достъп до loopback: задай `$env:PUKANKOV_INMEMORY_API="1"` и изпълни `npm run build` преди `npm run test:e2e`. Браузърът получава реалните HTTP отговори на FastAPI чрез тестов stdin/stdout мост вместо TCP. Тази проверка не удостоверява достъпността на порт 8000.

Playwright създава отделна SQLite тестова база в локалната `.test-artifacts/` папка, генерира нова случайна администраторска парола и стартира изолирани сървъри на 5174 и 8001. Не използва локалните потребители/поръчки на сайта. При рестартиране паролата е различна. Тестовият helper `scripts/e2e_server.py` не е production bootstrap и отказва да работи без изрична тестова конфигурация.

В среда с ограничена Temp директория използвай `python -m pytest tests -q --basetemp=ABSOLUTE_PATH_TO_NEW_WORK_TEST_FOLDER`. За браузърен cache извън системния профил задай `PLAYWRIGHT_BROWSERS_PATH` преди install и тестовете.

Покритие: регистрация/вход/изход, роли и CSRF, търсене и филтри, конкурентни места, изтичане, права върху поръчки, промокодове и сървърни суми, идемпотентност, отказано демо плащане, еднократна проверка на код, обща наличност за сайт и автомат, роли/ключове на устройства, миграция на стар QR билет, административни филми/прожекции, профил и rate limit. Браузърните сценарии проверяват покупка, отказ и нов опит, шестцифрени билети, липса на картови данни в API, любими, търсене, модален прозорец, всички публични страници, администрация и 360/390/768/1024/1440/1920 px.

## Известни ограничения и следващи стъпки

- **Реални плащания не са интегрирани.** `PAYMENT_MODE` извън `simulation` (или стария alias `demo`) връща 503; webhook маршрути за неконфигурирани доставчици също връщат 503 и не могат да потвърдят билет. Нужни са избран PSP, ключове, подписани/idempotent webhooks, възстановявания и integration тестове. Текущата идемпотентност покрива картовия симулатор.
- SQLite е само за локална демонстрация; сериализира транзакциите чрез `BEGIN IMMEDIATE`. PostgreSQL използва `SELECT FOR UPDATE` и уникално ограничение за място/прожекция. PostgreSQL конкурентност и Docker трябва да се проверят в реална PostgreSQL среда преди внедряване.
- Всички Python timestamps са timezone-aware UTC. PostgreSQL използва `TIMESTAMPTZ`; SQLite adapter възстановява UTC при четене. API издава ISO timestamps с `+00:00`, а кино програмата се показва в `Europe/Sofia`.
- Ролите и жанровете са опростени (role поле и JSON жанрове). Няма отделна пълна нормализирана схема за reviews, notification subscriptions или маркетингови съгласия. Няма напомняния или фиктивни потребителски отзиви.
- Филтрите по кирилица използват сървърно casefold върху малкия демо каталог; за големи каталози премини към PostgreSQL full-text/trigram индекси и нормализирани жанрове.
- Ограничителят на заявки е в паметта на един процес. За няколко workers са нужни Redis/общ лимитер, durable email queue/retries и управление на сесиите.
- Администрацията не е пълна ERP система: няма редакция на адреси/схеми през UI, редакция на съществуващи промокодове, реални refunds, графика за запълняемост, автоматична GDPR анонимизация или SMTP билетни attachments. Залите могат да се добавят; местата се управляват чрез защитен API и не могат да се променят при съществуващи claims.
- Възстановяване на парола изисква SMTP. Няма email verification. Няма JWT refresh поток: използвани са отзоваеми, непрозрачни 12-часови cookie сесии; никакъв auth token не се съхранява в localStorage.
- PDF е през print dialog, не server-side download. Шестцифреният код е уникален в базата и не се преиздава. Пространството е 900000 кода; преди изчерпване трябва по-дълъг формат. Административният валидатор приема код и прожекция; хардуерният API изисква отделен bearer ключ.
- `0001` е замразена начална миграция; при бъдещо развитие добавяй отделни Alembic revisions. Не използвай downgrade върху база с реални поръчки.
- 15-те филмови концепции, сюжетите и SVG илюстрациите са създадени за проекта. Генериране: `python scripts/generate_original_art.py`. Виж [произход на изображенията](docs/asset-credits.md). Google Fonts се зарежда външно. Линковете към социални мрежи са общи, няма измислени официални профили.
- Преди реална услуга: юридически оператор и контакти, преглед на политики и срокове, HTTPS, конфигурация на домейн и canonical/sitemap, мониторинг, резервни копия, външно security/a11y ревю и натоварващи тестове. Production режимът изисква PostgreSQL и Secure cookies.

## Автомат и входен контрол

Публичен HTTPS API с общата база на сайта и избор на филм/час/място. ESP32 потвърждава чрез `payment_success`, без картови данни: [docs/public-device-api.md](docs/public-device-api.md). Launcher: `python scripts/run_public_api.py --cloudflared PATH_TO_CLOUDFLARED`. Запази един и същ `DATABASE_URL` за сайта и gateway. Миграция `0004` премахва картовия регистър. Поръчките и историята на плащанията се запазват.

[docs/devices.md](docs/devices.md) описва общия API за ESP32/Wokwi и Raspberry Pi, създаване/отзоваване на ключове, продажба от автомат и атомарно еднократно валидиране на код. Примерен Pi клиент: [`hardware/raspberry-pi/validate_ticket.py`](../hardware/raspberry-pi/validate_ticket.py). Firmware и реална Wokwi симулация са следващ етап.
