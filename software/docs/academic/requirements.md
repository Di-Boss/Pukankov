# Изисквания и проследимост

## Обхват

Системата обединява онлайн продажба и общ интерфейс за билетен автомат и входен контрол. Реализираната част включва уеб приложение, база, административен интерфейс и API за устройства. ESP32 firmware и механиката за снаксове са извън текущата реализация.

## Функционални изисквания

| ID    | Изискване / критерий                                    | Реализация                                                | Проверка                                     |
| ----- | ------------------------------------------------------- | --------------------------------------------------------- | -------------------------------------------- |
| FR-01 | Публичен каталог с 15 авторски филмови концепции        | `app/original_catalog.py`, `api/public.py`, React каталог | Backend каталог; браузърни филтри            |
| FR-02 | Потребителски профил и достъп само до собствени поръчки | `api/auth.py`, `api/booking.py`                           | Сесии, ownership, роли                       |
| FR-03 | Временен hold до 8 места за 300 секунди                 | `services/reservations.py`                                | Конкурентност и изтичане                     |
| FR-04 | Сървърни цени, промокодове и избран учебен резултат     | Checkout service, `SimulatedCardPayment.tsx`              | Успех/отказ и payload                        |
| FR-05 | Уникален шестцифрен код за всеки издаден билет          | `services/tickets.py`, DB constraint                      | Формат, уникалност и колизия                 |
| FR-06 | Еднократна проверка за конкретна прожекция              | `validate_ticket`, staff/device API                       | Повторение, грешна прожекция, два валидатора |
| FR-07 | Административни операции и одит                         | `api/admin.py`, React администрация                       | CRUD, права, одит                            |
| FR-08 | Общ инвентар за сайт и kiosk                            | Общ service слой                                          | Device/API интеграционен тест                |
| FR-09 | Разделени права за kiosk и validator                    | Device model, bearer dependency, CLI                      | Роля, отзоваване, зала, лимит                |
| FR-10 | Историята се запазва при замяна на QR с код             | Alembic `0002`, seed visibility                           | Миграция на стар платен/използван билет      |

Пътищата в таблицата са спрямо `software/backend/`, освен React компонентите в `software/src/`.

## Нефункционални изисквания

| ID     | Критерий                                          | Основание и граница                                          |
| ------ | ------------------------------------------------- | ------------------------------------------------------------ |
| NFR-01 | Едно място не може да бъде заявено от двама       | Транзакции + уникално DB ограничение; проверено върху SQLite |
| NFR-02 | Повторен checkout не дублира билети               | Уникален hold/order и идемпотентен service                   |
| NFR-03 | Тайните не са част от изходния код                | Хеширани сесии/ключове, environment, Git ignore              |
| NFR-04 | Няма съхранение или изпращане на картовите полета | Само локално React състояние и браузърен payload тест        |
| NFR-05 | Работа на тесен и широк екран                     | Проверени шест ширини; не е пълен WCAG одит                  |
| NFR-06 | Възпроизводима схема и проверка                   | Alembic, lockfile, pytest, Playwright, GitHub Actions        |
| NFR-07 | Без разрешение при неизвестен статус              | Хардуерен договор; физическата проверка предстои             |

## Отложени изисквания

GPIO, схема и firmware; билетен принтер; дозиращи механизми и сензори; банков доставчик; билетни имейли; многопроцесен rate limiter; оценка на PostgreSQL при натоварване. Няма заявена измерена пропускателност, надеждност на физически компоненти или реална финансова операция.
