# Постоянен HTTPS адрес за ESP32

Публичният device API остава на порт 8002 и използва същата база като сайта.
`START-STABLE-API.cmd` публикува този API през изрично зададен ngrok домейн.
Скриптът не заменя адреса със случаен тунел при грешка. Ключът за терминала и
HTTP маршрутите остават същите.

## Еднократна настройка

1. Създай [безплатен ngrok акаунт](https://dashboard.ngrok.com/signup).
2. Инсталирай ngrok от [официалната страница за Windows](https://ngrok.com/download/windows).
   Използвай посочената там версия от Microsoft Store. След инсталацията отвори
   нов терминал, така че `ngrok` да се намира в PATH.
3. В [Domains](https://dashboard.ngrok.com/domains) копирай автоматично зададения
   домейн. Не избирай платен потребителски домейн.
4. Стартирай `software/START-STABLE-API.cmd`. Въведи публичния домейн, а после
   [authtoken](https://dashboard.ngrok.com/get-started/your-authtoken) в скритото
   поле на терминала. Не изпращай токена в чат и не го поставяй във firmware.
5. След успешна HTTPS проверка скриптът изписва `URL https://...ngrok-free...`.
   Изпрати целия ред веднъж в Serial Monitor на ESP32. Устройството го запазва в NVS.

На този компютър предоставеният `outputs/START-STABLE-API.cmd` използва готовите
Python зависимости и съществуващата база на сайта. Версията в `software/`
използва Python и зависимостите от собствената ти среда. За ngrok извън PATH:

```powershell
python scripts/run_stable_api.py --ngrok C:/Tools/ngrok.exe
```

## Следващи стартирания

Стартирай същия файл. Съхраненият домейн се подава изрично чрез `--url`, така че
остава същият след рестартиране. Ако API вече работи на порт 8002, скриптът го
проверява и използва. Ако портът е свободен, стартира device API с `--local-only`.
Използва се `backend/.env`; при отделна база подай `--database-path`.

Остави прозореца, компютъра и интернет връзката включени. Постоянният адрес не
осигурява работа при изключен компютър. За денонощна услуга са нужни постоянно
включен сървър и обща база за сайта и device API.

След успешния преход спри старите localhost.run и Cloudflare Quick Tunnel
прозорци. Скриптовете на диска вече запазват `url_mode=stable` и не презаписват
постоянния URL при пускане на временен тунел. Вече стартираните стари процеси
трябва да бъдат спрени отделно.

Настройките се пазят само в игнорираната `.local/` папка:

- `stable-api.private.json`: домейн и ngrok authtoken.
- `ngrok.private.yml`: локална конфигурация на агента.
- `stable-api-state.json`: адрес и състояние, без токен.
- `ngrok.private.log`: локален диагностичен лог.

Използвай `--setup` за смяна на настройките и `--check` за локална проверка на
ngrok конфигурацията. Скриптът изключва HTTP инспекцията на агента и проверява
публичния health endpoint преди да запази новия адрес за ESP32.

## Граници и проверки

ngrok предоставя един автоматично зададен dev домейн на безплатен акаунт и
той не се сменя при рестартиране. Планът има лимити за заявки и трафик; виж
[актуалните условия](https://ngrok.com/docs/pricing-limits/free-plan-limits).

Подготовката и автоматичните проверки на launcher-а са отделни от реалната
активация. В момента на добавянето няма предоставен ngrok акаунт или реален
домейн, затова публичен ngrok endpoint и ESP32 HTTPS връзка към него не са
отчетени като изпитани. След настройката трябва да се потвърдят `TLS_OK`,
`HTTP 200` и `READY_MOVIES` на ESP32. Съществуващият скеч поддържа Google, ISRG
и Amazon CA корени; проверката на сертификата остава включена.
